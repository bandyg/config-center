## 1. 核心目标

### 1.1 总体目标

以 **Kiosk Config Center 用户体验升级** 为主题，通过 3 个迭代（共 6 周）完成现有界面的交互体验重构，使运维人员能够高效、安全、直观地完成日常配置管理工作。

### 1.2 关键成功指标 (KSI)

| 指标 | 当前基线 | 目标值 | 测量方式 |
|------|---------|-------|---------|
| 单次配置编辑操作耗时 | 约 3-5 分钟 | **≤ 1 分钟** | 用户操作计时测试 |
| 批量 10 台推送操作完成率 | - | **100% 成功率** | 系统日志统计 |
| JSON 编辑错误率 | 约 30% 操作出错 | **≤ 5%** | 错误提交统计 |
| 用户满意度评分 | - | **≥ 4.0/5.0** | NPS 调研 |
| 配置差异识别耗时 | 约 5-10 分钟 | **≤ 2 分钟** | 用户操作计时测试 |

### 1.4 不纳入范围

| 排除项 | 原因 | 后续规划 |
|--------|------|---------|
| 用户认证/权限管理 | 内部工具当前无此硬性需求 | 下一版本规划 |
| 配置模板/预设系统 | 需要更多用户使用数据积累 | 迭代 4+ |
| 终端自动发现/注册 | 静态 YAML 在当前规模下足够 | 终端超 200 台时评估 |
| 移动端适配 | 运维场景以桌面为主 | 视需求反馈决定 |
| 日志/监控面板 | 超出"纯配置管理"项目定位 | 如项目定位扩展则纳入 |

## 3. 资源配置方案

### 3.1 人员配置

| 角色 | 人数 | 投入时间 | 职责 |
|------|------|---------|------|
| **后端开发** | 1 人 | 全周期（6 周 × 100%） | FastAPI 后端开发、API 设计、数据持久化 |
| **前端开发** | 1 人 | 全周期（6 周 × 100%） | 前端交互开发、编辑器集成、UI 组件 |
| **产品经理** | 1 人 | 兼职（每周 2 天） | 需求澄清、验收确认、用户沟通 |
| **QA 测试** | 1 人 | 迭代二开始介入 | 功能测试、回归测试、性能测试 |
| **技术负责人** | 1 人 | 兼职（架构评审） | 技术方案评审、风险把控 |

### 3.2 环境与工具

| 资源 | 说明 |
|------|------|
| 开发环境 | 现有 Python 3.11 + FastAPI 开发环境 |
| 版本管理 | GitHub (现有仓库) |
| CI/CD | GitHub Actions（现有流程）+ 新增前端构建步骤 |
| 测试终端 | 现有 bhs-4 管理服务器 + 至少 2 台测试终端 |
| 打包工具 | PyInstaller（现有，需验证与前端构建产物兼容） |

### 3.3 关键技术决策

| 决策项 | 方案 | 理由 |
|-------|------|------|
| JSON 编辑器 | CodeMirror 5 + JSON 插件 | 体积小（~150KB gzip），无外部依赖，兼容 Jinja2 无构建流程 |
| Diff 库 | diff-match-patch (Google) | 成熟稳定，支持行级 diff |
| 配置历史存储 | JSON 文件（`history/` 目录）+ 时间戳命名 | 维持零数据库原则，后续可迁移到 SQLite |
| 进度指示方案 | 后端 SSE (Server-Sent Events) + 前端 EventSource | 实时性好，实现简单，不增加依赖 |
| 树形浏览 | 纯 CSS/JS 实现递归展开/折叠 | 不引入额外框架，保持打包体积 |

### 6.2 回退计划

若迭代一因技术障碍（如 R1 发生）导致严重延期：

```
方案A (首选): 降低前端复杂度
  • 放弃 CodeMirror 集成，改用 simple-mde 级轻量编辑器
  • 仅实现 JSON 格式化 + 校验定位 + 编辑区放大

方案B (备选): 拆分迭代一
  • 迭代一-a (第1周): JSON格式化 + 状态加载 + 批量选择重构（核心功能先行发布）
  • 迭代一-b (第2周): Diff预览 + 树形浏览 + 校验定位（后续交付）
```

## 7. 验收标准

### 7.1 通用验收标准（所有功能）

| 编号 | 标准 | 验证方式 |
|------|------|---------|
| AC-G1 | 所有页面在 Chrome/Edge 最新版本上正常渲染和交互 | 手工测试 |
| AC-G2 | PyInstaller 打包后的单 EXE 可正常启动并访问所有页面 | 打包测试 |
| AC-G3 | 单个 API 请求超时时间 ≤ 5s，有友好的超时提示 | 性能测试 |
| AC-G4 | 终端离线时页面不会崩溃，有明确的离线提示和引导 | 场景测试 |
| AC-G5 | 所有新增代码通过 lint 检查，无 console error | 代码审查 |

## 1. 简介

Kiosk Config Center 是一个集中管理 Kiosk 终端配置的 Web 工具。它通过 HTTP 代理访问各终端上的 `config-serv` 服务，提供统一的图形化管理界面。

### 1.1 核心功能

| 功能 | 说明 |
|------|------|
| **终端状态监控** | 实时查看所有终端的在线/离线状态、健康度评分、配置版本号 |
| **单机配置编辑** | 查看和修改单台终端的全部配置项，支持 JSON 编辑器、树形浏览 |
| **批量配置推送** | 选择多台终端或整个分组，一次性推送配置修改 |
| **配置对比** | 对比多台终端同一配置项的差异，支持导出对比报告 |
| **配置历史与回滚** | 查看配置修改记录，一键回滚到历史版本 |

### 1.2 访问地址

启动后默认访问：**http://localhost:8300**

## 2. 快速入门

### 2.1 启动方式

**方式一：双击 EXE（推荐）**
1. 双击 `KioskConfigCenter.exe`
2. 控制台窗口自动启动，浏览器自动打开 `http://localhost:8300`

**方式二：Windows 服务（开机自启）**
1. 以管理员身份打开 PowerShell
2. 执行：`.\scripts\install-service.ps1 -Action install`
3. 服务名为 `KioskConfigCenter`，自动开机启动

**方式三：Python 开发模式**
```bash
python run.py
```

### 2.2 首页概览

打开首页后，您会看到：
- **统计卡片**：终端总数、在线数量、分组数（服务端直接渲染，无闪烁加载）
- **搜索与筛选**：按 IP、别名、分组名搜索终端
- **终端表格**：每台终端的在线状态、健康度评分、配置版本号

### 2.3 基本操作流程

```
查看终端状态 → 进入详情页 → 修改配置 → 确认保存 → 验证结果
```

### 2.4 DC 模式部署（总行集中管理）

**适用场景**：在总行（DC）Server 上运行，通过各分行（BC）Server 代理，统一管理全行约 3000 台终端。

**网络拓扑**：
```
DC Server (总行) ── DC 局域网 ── BC Server (分行, ×100) ── Terminal 局域网 ── Terminal (×30~50)
```

- BC Server 有**两张网卡**：一张连 DC 局域网（DC 可达），一张连 Terminal 局域网
- DC **无法直连** Terminal，必须通过 BC 代理

**部署步骤**：

1. 确认各 BC Server 上已运行 Kiosk Config Center（BC 模式，默认 `:8300`）

2. 编辑 DC 上的 `servers.yaml`：
```yaml
mode: dc
branches:
  - id: sz
    name: 深圳分行
    url: http://10.66.1.100:8300    # ← BC 的 DC 侧 IP
  - id: bj
    name: 北京分行
    url: http://10.66.2.100:8300
  # ... 依次添加所有分行（约 100 台）
```

3. 设置环境变量并启动：
```powershell
$env:KIOSK_MODE="dc"
python run.py
```

4. 浏览器访问 `http://localhost:8300`，首页自动聚合所有 BC 的终端列表

**DC 模式与 BC 模式的区别**：

| 功能 | BC 模式 | DC 模式 |
|------|---------|---------|
| 终端列表 | YAML 文件管理 | 从各 BC Server 聚合 |
| 添加终端 | 支持 | 不支持（在各 BC 上操作）|
| 扫描子网 | 支持 | 不支持 |
| 首页加载 | SSR 实时检测 | 缓存（30s 刷新）|
| 分支信息 | 不显示 | 显示分行名称列 |
| 健康度 | 0-100 分 | 在线/离线 badge |

## 3. 终端列表仪表盘

### 3.1 界面布局

| 区域 | 内容 |
|------|------|
| 顶部导航 | 终端列表 / 批量操作 / 配置对比 三个页面入口 |
| 统计卡片 | 终端总数（绿色数字）、在线数、分组数 |
| 搜索栏 | 搜索框 + 分组下拉筛选 + 刷新按钮 |
| 终端表格 | 状态、别名、IP、分组、健康度、配置版本、操作链接 |

### 3.2 健康度评分

健康度评分范围 0-100，颜色标识：
- **绿色 (≥80)**：终端在线，配置完整，版本正常
- **黄色 (50-79)**：终端在线但存在异常（如缺少配置项）
- **红色 (<50)**：终端离线或存在严重问题

### 3.3 分页导航

当终端数量超过 20 台时，底部分页控件自动出现，支持页码跳转和前后翻页。

### 3.4 刷新状态

- 页面首次加载的状态由服务端直接渲染，**无需等待 JS 执行**
- 点击「刷新」按钮可异步更新所有终端的最新状态

## 4. 终端配置详情与编辑

### 4.1 进入详情页

在终端列表中点击目标终端的「查看」链接，进入配置详情页。

### 4.2 信息栏

页面顶部显示终端的基本信息：IP、端口、分组、在线/离线状态。

### 4.3 配置项折叠面板

每个配置项是一个可折叠的面板（如 `serviceConfig`、`terminalFunction` 等），点击标题栏展开/折叠。

### 4.4 编辑器模式与树形浏览

每个配置项提供两种浏览模式，通过 Tab 切换：

**✏️ 编辑器模式（默认）**
- 基于 CodeMirror 的 JSON 编辑器
- 语法高亮、行号显示、括号匹配
- 工具栏按钮：
  - **格式化** — 一键美化 JSON 缩进
  - **树形预览** — 切换到树形浏览模式
  - **预览变更** — 保存前查看修改前后的差异比较
  - **全屏** — 编辑器全屏显示

**🌳 树形浏览模式**
- JSON 以树形结构展示，可展开/折叠节点
- 工具栏按钮：
  - **展开全部** / **折叠全部**
  - **切换到编辑** — 返回编辑器模式

### 4.5 保存配置

1. 在编辑器中修改配置内容
2. 点击「保存」按钮或按 `Ctrl+S`
3. 弹出确认弹窗，显示修改前后的差异对比（绿色=新增，红色=删除）
4. 点击「确认保存」执行写入
5. 保存成功后显示绿色确认提示

### 4.6 离线状态

当终端离线时，页面显示：
- 橙色提示信息"终端离线"
- 建议操作指引
- **「重试连接」**按钮 — 点击后重新检测终端状态，恢复后自动刷新页面

## 5. 批量操作

### 5.1 选择目标终端

**按分组筛选（推荐）**
1. 点击分组标签（如「管理服务器」）→ 自动勾选该分组下所有终端
2. 可在已选基础上单独增加或取消个别终端
3. 分组标签旁显示已选数量

**手动选择**
- 点击终端条目勾选/取消
- 使用「全选」或「取消全选」快捷操作

**在线状态提示**
- 终端列表中显示在线/离线状态标签
- 列表上方显示在线终端数量汇总

### 5.2 编写配置内容

1. 从下拉列表选择要修改的配置项（中英文对照标注）
2. 在文本框中输入 JSON 格式的配置值
3. 支持「格式化 JSON」一键整理
4. 支持「预览变更」查看修改全文

### 5.3 执行推送

1. 点击「推送到选中终端」按钮
2. 确认弹窗显示目标终端列表和配置新值
3. 点击「确认推送」执行
4. 进度条实时显示推送进度
5. 完成后显示成功/失败统计：
   - ✅ **成功** — 终端及数量
   - ❌ **失败** — 终端、数量及具体错误原因

## 6. 配置对比

### 6.1 选择终端

勾选 2 台或以上终端进行对比（支持按住 Ctrl 多选配置项）。

### 6.2 选择配置项

- **单选**：直接点击选中一项
- **多选**：按住 `Ctrl` 键点击选择多项
- 配置项列表包含中文说明

### 6.3 查看对比结果

- 表格以「字段路径 | 终端1值 | 终端2值 | ...」形式展示
- **差异行**：橙底高亮 + 左侧橙色指示条 + `≠` 标记
- **相同行**：灰色弱化显示
- 顶部统计摘要：差异项数 / 相同项数 / 总字段数

### 6.4 导出对比报告

支持两种导出格式：
- **CSV** — 可用 Excel 直接打开（UTF-8 BOM 编码）
- **Markdown** — 可用于文档嵌入或提交到 Git

## 7. 配置历史与回滚

### 7.1 查看修改历史

在终端详情页的终端列表中，点击表格中的 📋 图标进入配置修改历史页面。

> 每次通过 Config Center 修改配置都会自动记录历史：修改时间、修改前后的配置值。

### 7.2 回滚操作

1. 在历史记录中找到要回滚到的版本
2. 点击「回滚到此版本」
3. 系统自动将对应版本的配置值写入终端
4. 回滚操作本身也会记录在历史中

## 8. 常见问题

### Q1: 终端显示离线怎么办？

1. 确认终端上的 `config-serv` 服务是否正常运行
2. 确认管理服务器与终端的网络连通性（内网/Tailscale）
3. 在详情页点击「重试连接」按钮
4. 如问题持续，请在终端上执行 `curl http://localhost:8081/` 检查 config-serv 是否响应

### Q2: 保存配置后没有生效？

1. 确认保存后出现绿色「✅ 保存成功」提示
2. 某些配置项需要重启终端应用才能生效（请参考 config-serv 文档）
3. 检查终端是否在线

### Q3: 批量推送部分失败怎么办？

- 结果列表中会显示失败终端的具体错误原因
- 常见原因：终端离线、JSON 格式不合法、config-serv 拒绝写入
- 可针对失败终端重新执行推送

### Q4: 如何备份配置？

- 目前 Config Center 不直接存储配置，所有配置读取自各终端
- 配置修改历史按终端和配置项存储为 JSON 文件
- 建议定期使用「配置对比」功能导出 CSV 报告作为备份

### Q5: 如何将 Config Center 注册为 Windows 服务？

以管理员身份运行 PowerShell：
```powershell
.\scripts\install-service.ps1 -Action install
```
卸载服务：
```powershell
.\scripts\install-service.ps1 -Action uninstall
```

### Q6: 配置文件在哪里？

- 终端列表：项目根目录下的 `terminals.yaml`
- 配置历史：`app/history/` 目录下按 IP 分目录存储 JSON 文件
